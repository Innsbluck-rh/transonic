## 概要

- これは今後のtransonicにおけるADR作成のためのテンプレート兼READMEファイルです。
- ADRの作成や記述の規則などについて記載します。

## 作成にあたって

### 形式

- /adr内に.md形式で作成してください。
- N-の形で連番で作成してください。
- ファイル先頭には以下の形でヘッダーを残してください。

```md
<!--
author:   innsbluck / Codex / etc
date:     YYYY-MM-dd HH:mm
version:  [作成当時のCargo.toml記載のバージョン]
-->
```

### 〇 やっていいこと
- transonicにおけるADRは厳格なドキュメントではなく、その時々の意思決定を残すためのものとして機能します。実装における決定はもちろん、残すべきだと思った記法や実装のDOやDONTを書き残す目的でも使用します。
- 情報がいつ書かれたものかはヘッダーに書かれたバージョンや日時にて判断し、あまりにも古い情報の場合はそれが本当に現状に即したものかどうかを疑ってください。
- ADRは実装してからの感触やその時の意思を記録するものであり、その時たまたま見つけたメインの対象と関係のない不具合や不整合なども併記してかまいません。
- 記法は基本的には自由ですが、このテンプレートと比してあまりにも逸脱したものにならないようにしてください。

### ✕ やってはいけないこと 
- **今後の展望や予定を書くことは一切しないでください。** これはADRをTODOリストにしないために非常に重要です。
- **今後何をするかをADRに書くこと、今後何をするかを確認するためにADRを参照すること、これらはどちらも厳禁です。** あくまで過去の決定や意思を参照して参考にするためのものであることに注意してください。
- また、本プロジェクトにおけるADRはシステム構成などの固いドキュメントを書くのにも適したものではありません。それらはdocs/などに書いてください。
- 文法においては不必要に体言止めを使用しないでください。また、なるべく平易で一般的な表現を使用し、不自然な言葉の使用（"その線で"、"素直に"などの資料として不適切な語彙を含む）は避けてください。


## 将来的な仕様改変について

- ADRで残した情報が古くなったり、過去行った意思決定が後に取り下げられることは今後多くあると思われます。
  情報の食い違いを防ぐため、大きな仕様の転換があった場合はadrを見直し、修正してください。
- ただし、あまりにバージョンや作成日時が古いADRにおいてはそもそも参照の時点で古い情報と気づけるため、過去を過度に遡ってまで修正点を見つけることはしないべきです。
- 修正するときは修正日時を書いたうえで取り消し線で前の情報を消し、修正後どうなったかをその下に記載してください。

### 修正の例

- ~~熟考の末、物は下から上に落ちることに決定した。~~\
  (2026-03-24 10:52) これは認識が誤っており、物は上から下に落ちるように方針を変更しました。
